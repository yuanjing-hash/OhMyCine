# 实施计划

## 执行顺序

1. 完成并复核子任务 `08-27-media-identity-search-coverage` 的规划产物与上下文清单。
2. 用户批准本次最终规划摘要后，只启动子任务 1；实现、检查、必要 spec 更新并提交/归档该子任务。
3. 重新读取子任务 2 对子任务 1 的实际契约依赖，若无实质漂移则启动 `08-27-automatic-tv-subscriptions`；若契约有实质变化，先更新规划并重新请求批准。
4. 实现、检查、必要 spec 更新并提交/归档子任务 2。
5. 执行父任务跨子任务集成复核，不启动无直接代码工作的父任务。

## 父任务集成检查

- [ ] 推荐、关键词海报搜索、相关作品和类似作品共用稳定 TMDB 详情路由。
- [ ] 默认搜索路径不再把自由文本直接当 PT/BT 资源搜索；高级原始关键词入口仍可达。
- [ ] 手工身份搜索和订阅 Worker 复用同一名称生成、站点搜索、资源识别和去重契约。
- [ ] 详情覆盖率和订阅缺集目标来自同一 `MediaCoverage` 服务。
- [ ] 订阅创建/编辑完整保留执行策略修订，默认值变更不会改变旧订阅。
- [ ] 自动下载走既有 `DownloadService → recognition → Transfer → import → refresh/notify`。
- [ ] owner/RBAC、安全 DTO、审计、事件和日志边界通过跨层测试。
- [ ] Server 架构和 roadmap 与最终完成状态一致；再次确认 OpenAPI 文件是否存在。


## 风险与回滚点

- 多名称搜索可能放大站点请求量：名称数、站点并发、每站分页和单次结果数必须有硬上限，并允许取消。
- 覆盖率错误会造成误下载：任何未知、未来或无法稳定匹配的集必须 fail closed。
- 自动择优可能选择错包：必须有确定过滤、可解释排序、歧义阻塞和每集幂等 claim。
- 配置修订与运行并发可能漂移：Job 固定启动修订，提交下载前再次核对订阅状态、缺集事实和已有活动任务。
- 回滚先停用调度和 UI 自动入口，不删除 additive 数据，不影响手工下载和既有流水线。
