# 修复离线媒体投影与下载线程设置

## Goal

让下载文件成为原媒体的本地可用副本，而不是独立媒体库或重复媒体卡片；删除本地副本后立即恢复原来源播放。同时让任务并发与单任务线程默认均为 1，并让暂停继续/失败重试采用用户最新保存的线程设置。

## Background

- `OfflineDataSource` 当前既承担内部离线解析，又被加入侧边栏、首页聚合和搜索，下载完成后会投影出第二张媒体卡片。
- 删除离线文件后，离线数据库记录已经失效，但持久化首页缓存仍可能保留 `__offline__` 卡片，点击后显示“详情不可用”。
- 原媒体已有本地优先播放和下载徽标能力，应复用原来源身份，不应再公开独立“已下载”媒体库。
- Rust 下载器每次执行会读取最新设置，但可复用的旧分段布局不会随线程数变化，暂停继续后仍可能使用旧线程数。

## Requirements

1. `OfflineDataSource` 可继续作为内部冷启动/附件解析能力，但不得出现在用户侧边栏、首页聚合、全局搜索或独立媒体库中。
2. 启动时清理旧版本持久化显示缓存中的 `__offline__` 栏目、卡片和来源快照，避免升级后继续显示幽灵媒体。
3. 下载完成只更新原媒体卡片的“已下载/部分下载”徽标；播放仍通过原来源身份先解析本地文件，失败再回退网络来源。
4. 下载管理中的详情入口应打开原来源媒体详情，不再导航到独立离线来源。
5. “删除记录和文件”完成后必须刷新离线索引、清理内部离线来源缓存和旧显示投影，原媒体徽标消失，随后播放走非本地来源。
6. 默认同时下载任务数为 1，默认单任务下载线程数为 1；不覆盖用户已经保存的配置。
7. 新任务使用最新设置；暂停继续、失败重试重新读取最新线程数。正在传输的任务不因设置保存而强制中断。
8. 当恢复任务的旧分段布局与最新线程数不同且实体一致时，安全重建分段布局，尽量保留每个新分段开头连续完成的字节；无法安全 Range 时降级单线程。
9. 不修改 Server。

## Acceptance Criteria

- [x] 下载完成后首页不新增“离线内容/已下载”来源或重复媒体卡片。
- [x] 升级后旧 `__offline__` 首页缓存被自动清除。
- [x] 原媒体卡片下载完成后显示下载徽标，并优先播放本地文件。
- [x] 删除记录和文件后，下载徽标及旧离线卡片立即消失，原媒体播放回退在线来源。
- [x] 下载管理的详情入口打开原媒体详情。
- [x] 新安装默认并发任务数和线程数均为 1，已有保存设置保持不变。
- [x] 暂停或失败任务在继续/重试后使用最新线程数，旧分段不会继续启动旧数量的工作线程。
- [x] lint、typecheck、build、Rust fmt/check/clippy/test 与相关专项脚本通过。
- [x] `git diff --name-only -- server` 为空。

## Out of Scope

- 删除内部离线数据库或 `OfflineDataSource` 的冷启动解析能力。
- 改变下载附件范围或 Server 下载/入库流程。
- 保存设置时强制中断正在下载的任务。

## Key Decisions

- 离线是原媒体的本地可用状态，不是新的用户可见媒体来源。
- 已下载与已播放状态相互独立。
- 线程设置在下一次任务启动、暂停继续或失败重试时生效；活动传输不热切换。
