# Server 下一代媒体识别引擎

## Goal

将 Server 现有的“标题清洗后取 TMDB 第一条结果”升级为来源无关、结构感知、多语言、可解释、可纠错、可量化回归的媒体识别引擎。首要用户价值是：115、OpenList/Alist、CloudDrive2、本地文件和下载器产生的常见中文/英文/PT 命名能够稳定自动入库；识别失败时不重复下载已完成的数据。

## Background and Confirmed Facts

- 失败样本为 `Ming Dynasty in 1566 HQ -BlackTV`，来源是已经完成的 115 离线下载；共 49 个媒体文件，已正确推断为电视剧和年份 2007，但最终错误码是 `tmdb_no_match`，随后被转成 `transfer_media_unrecognized`。
- 当前标题清洗未把 `HQ` 视为资源规格，尾部发布组规则不兼容 ` -BlackTV`，因此没有产生干净候选 `Ming Dynasty in 1566`。
- 当前 TMDB 首轮会比较本地化标题和 `original_title` / `original_name`，但没有 alternative titles / translations 二次验证；排序只消费搜索结果第一项，标题相似度只有精确、包含、其他三档。
- 当前类型由单个候选前置决定；缺少 multi-search、跨类型安全回退和基于文件集合的结构证据评分。
- 当前管理界面对已下载完成但识别失败的 115 任务显示“重试下载”，会误导用户再次下载 294.4 GiB；产品需要“自动重新识别 / 可选显式 ID 纠错 / 继续入库”的恢复路径。
- MoviePilot 的正常识别和自动整理链直接消费单一自动匹配结果，不存在 Top-k 候选人工确认步骤；其“重新识别”允许留空 ID 再次自动识别，也允许失败后填写数据源原生 ID 强制纠错。OhMyCine 不得把人工候选选择设计成默认流程。
- MoviePilot v3 公开源码使用 GPLv3；只借鉴可观察行为、测试维度和架构，不复制源码或大段正则。
- Emby 当前 Server 闭源；可研究当前官方命名文档以及公开的 Emby.Naming（MIT，最后提交 2019-05-16），但不得把旧公开实现等同于当前 Emby 内部算法。

## Requirements

### R1. 统一结构化输入

- 识别输入必须保留包名、主文件名、父目录层级、文件数量、视频文件集合、季集分布、光盘结构和来源类型等事实。
- 识别器只能接收 provider-relative、安全且有界的路径/名称事实；不得接收绝对路径、凭据、115 文件 ID 或可重放 URL。
- 同一引擎必须服务下载入库和现有媒体库扫描，避免两套识别规则漂移。

### R2. 多阶段解析与候选生成

- 解析必须区分标题事实与资源规格：中文/英文标题、年份、季、集、完结范围、版本、分辨率、来源、编码、音轨、字幕、发布组、光盘/多段结构。
- 候选必须由多个来源和多个清洗级别生成，而不是原地破坏唯一字符串；至少保留原始、去发布组、去规格、去季集、去年份及中英文分离候选。
- 发布组处理必须兼容 `-Group`、` -Group`、`- Group`、`[Group]` 等常见形态，并结合位置与周边规格判断；不能只依赖有限白名单，也不能把标题中的合法连字符尾词盲删。
- 资源规格至少覆盖 MoviePilot/Emby/现有回归语料中的常见标记，包括本例的 `HQ`。
- 数字标题（如 `Ming Dynasty in 1566`、`1917`、`3 Body Problem`）不得被年份或季集规则误删。

### R3. 类型与结构证据

- 类型判定必须综合显式 ID、库/分类上下文、SxxExx/季集表达、文件集合分布、Season/BDMV/VIDEO_TS 目录和单文件特征。
- 类型未知时允许 TMDB multi-search；首选类型查无结果时允许有界的跨类型回退。
- 类型证据与标题匹配冲突时不得静默强行匹配；引擎应继续用目录、文件集合、季集、年份、别名和跨来源证据自动消歧，全部自动策略仍无法达到验收阈值时才返回可解释的未识别结果。

### R4. 多语言召回与候选排名

- TMDB 候选比较必须覆盖本地化标题、原标题、alternative titles 和 translations，支持简繁转换、Unicode 规范化、大小写/标点/空白等价。
- 年份应支持精确匹配、合理的 `±1` 容差和“缺失不等于冲突”；季集年份可作为独立证据。
- 排名必须对一组候选统一评分，至少包含标题/别名相似度、类型证据、年份、季集结构、候选唯一性和有限的流行度先验；禁止继续使用“永远取第一条 + 包含即 0.82”的决策方式。
- 自动匹配阈值和冲突判定必须由 benchmark 校准，并能区分“无候选”“低置信”“候选冲突”“上游失败”；阈值的用途是防止静默误匹配，不是触发正常流程中的人工候选选择。

### R5. 显式身份与人工规则

- 继续支持并扩展安全的 TMDB ID 直达提示，兼容 Emby 常见的 `[tmdbid=123]`、`{tmdb-123}` 等格式；直达提示仍须从 TMDB 重新获取并验证类型和身份。
- 现有 Profile 识别词/内置包继续作为识别前处理能力，优先级必须清晰且可追踪。
- 显式 ID 纠正成功后可在本地保存规范化别名/规则，但规则必须有作用域、可查看、可撤销，不得把 provider ID 或绝对路径写入全局标题规则；该入口只作为自动识别失败后的高级兜底，不得成为正常入库步骤。

### R6. 可解释性与隐私

- 每次识别保存有界、无敏感信息的诊断：输入事实摘要、生成候选、TMDB 候选、各证据分数、最终阈值和拒绝原因。
- 管理界面应能展示“为什么匹配 / 为什么失败”，但不得显示绝对路径、凭据、115 文件 ID、签名 URL 或未脱敏上游响应。
- 日志和 API 诊断必须有大小上限，避免恶意名称造成日志放大、数据库膨胀或正则拒绝服务。

### R7. 失败恢复闭环

- 对已下载完成的任务提供“重新识别”，复用已完成 manifest/115 数据并继续 Transfer → Import → Notify，不重新提交离线下载。
- “重新识别”默认重跑完整自动识别链，不要求用户浏览或选择候选；若仍失败，人工介入区允许输入关键词搜索 TMDB，选择搜索结果自动取得 TMDB ID，也允许直接填写媒体类型与 TMDB ID，最终都必须通过可信 `GetByID` 路径校验后继续入库。
- “重试下载”只用于实际下载失败，不得用于已完成但识别失败的任务。

### R8. Benchmark 与回归门

- 建立脱敏、可版本化的识别语料，覆盖 115、PT、OpenList、本地文件、电影、电视剧、动漫、中英日韩、简繁、数字标题、发布组、资源规格、季集范围、多版本、BDMV/VIDEO_TS 和脏命名。
- 每条样本包含期望媒体类型、规范标题、年份/季集事实和期望远端身份（适用时），并标注允许歧义或必须拒绝的负样本。
- 质量指标至少包含 Top-1 正确率、Top-k 召回率、误匹配率、未识别率、解析正确率、外部请求数和耗时分位数。
- `Ming Dynasty in 1566 HQ -BlackTV` 的 49 集 115 manifest 必须成为硬性回归：解析出 `Ming Dynasty in 1566`、TV、2007，并匹配正确 TMDB 身份。
- 新引擎必须以同一 corpus 对比当前 OhMyCine、MoviePilot 可公开运行的解析行为和 Emby 公布的命名规范覆盖；“更强”以指标与失败样本集合衡量，而不是宣传性描述。

### R9. 搜索、目录与目标恢复一致性

- 搜索结果以顶部渠道切换、每站独立替换分页、卡片和组合筛选呈现；排序字段支持做种人数、发布时间和体积，并分别支持升序/降序，默认按做种人数降序；操作固定为“检测 / 手动检测 / 入库”。
- 自动检测成功也必须把经 `GetByID` 验证的身份绑定到 opaque claim；手动检测身份继续贯穿下载和最终入库。预识别失败时允许下载，最终识别明确使用真实 manifest。
- 媒体库持久相对根 `/` 必须同时展示 Storage 的实际可读根和“数据源根目录”语义，不能在编辑后看似丢失所选目录。
- 已下载完成且 Transfer 失败、尚未产生部分写入的任务允许修改目标媒体库，原子重建目标/Profile/命名快照并只重排 Transfer → Import；不得重新提交下载器。已产生写入、云端检查点或清理动作时必须拒绝。
- Player 本地原始数据源同步 provider-neutral 解析能力和冻结 corpus；ServerDataSource、Emby/Jellyfin 不二次识别。同一 Player 数据源 ID 修改物理根时不得复用旧扫描缓存。
- 修改全局下载暂存目录后，新 qBittorrent 任务必须继续使用创建时的绝对目录快照；同名分类仍指向旧目录时，Server 应安全更新分类、回读验证新路径，再设置任务位置并恢复。更新失败、未生效或路径越界不得恢复任务。旧版 Storage-relative 任务经自身旧快照安全解析后仍可继续，不能改用当前全局目录。

### R10. 全量敏感输入体验

- Player 与 Server Web UI 的 password、Cookie、token、passkey、API key、安全码及共享认证统一默认星号遮挡，并提供右侧眼睛切换当前输入原文；多行 Cookie 同样适用。
- 编辑已配置凭据时显示 `••••••••（已配置）`，不能再显示一个无法区分“未配置/已配置”的空框。
- 眼睛优先显示当前会话中新输入的替换值；用户主动点击时，也可按字段临时读取自己保存的第三方 Cookie、token、passkey、API Key 或外部服务账号凭据。
- Server 旧值只能通过专用的鉴权、CSRF、`no-store`、`connections.secrets.export` 权限与审计接口按白名单读取；普通列表/详情接口仍只返回逐字段 `configured` 布尔。Player 旧值只从本机安全凭据库读取。回显值必须与 `v-model` 分离，点击眼睛后直接保存不得重写凭据。
- OhMyCine 用户密码、Server/Player 会话与设备访问令牌、主密钥、302 签名密钥、内置或部署注入的 TMDB 凭据禁止回显。

## Acceptance Criteria

- [ ] AC1：本例无需自定义词即可产生干净候选 `Ming Dynasty in 1566`，保留标题内数字 1566，使用 49 集结构证据判定 TV，并命中正确 TMDB 条目。
- [ ] AC2：在冻结 benchmark 上，新引擎 Top-1 正确率高于当前引擎，且误匹配率不高于批准阈值；结果报告可重复生成并进入测试产物。
- [ ] AC3：英文原名、中文简繁名、日文/韩文原名及 TMDB alternative titles/translations 至少各有一条自动匹配回归。
- [ ] AC4：电影/剧集同名、数字标题、年份冲突、发布组像标题词、无结果和多候选近分等负样本不会被静默错误入库。
- [ ] AC5：解析和排名使用表驱动/fixture 测试；TMDB 网络交互使用受控假服务或 cassette，不依赖实时公网才能通过 CI。
- [ ] AC6：识别诊断能解释命中与拒绝，各字段有界且不包含绝对路径、凭据、provider ID 或签名 URL。
- [ ] AC7：已完成的 115 下载识别失败后可一键自动重新识别并继续入库；自动识别仍失败时，人工介入区可按关键词搜索 TMDB 并从结果自动取得 ID，或直接填写显式媒体 ID 纠错。过程中不会重新下载原数据，正常自动识别流程也不会要求用户执行候选选择。
- [ ] AC8：下载入库和媒体库扫描调用同一识别器，在等价输入上得到一致的规范身份与理由码。
- [ ] AC9：Go 测试、WebUI 测试、lint/静态检查和迁移回归全部通过；相关 API、Server 架构和识别规范文档同步。
- [ ] AC10：搜索页具备渠道 tabs、每站上一页/下一页、组合筛选、做种数/发布时间/体积的升序与降序，以及三个固定动作；默认做种数降序，自动/人工身份均安全贯穿入库。
- [ ] AC11：媒体库根目录显示不丢失；失败的已完成任务可安全重选目标且下载器调用数保持为零，部分写入任务被拒绝。
- [ ] AC12：Player v3 通过同一冻结识别 corpus，修改本地源根目录会失效旧 cache，Server/Emby/Jellyfin 权威 metadata 不进入本地识别链。
- [ ] AC13：仓库内没有绕过共享组件的敏感原生输入；新增/编辑场景的遮挡、按需旧值回显、已配置占位和禁用状态均通过检查。普通 API 不返回旧凭据；专用回显接口具备字段白名单、权限、CSRF、`no-store` 与无明文审计，且回显值不进入表单模型。
- [ ] AC14：修改全局暂存目录后，qBittorrent 旧分类路径会被更新并回读验证，任务按自己的暂存快照执行 `setCategory → setLocation → resume`；429/5xx 可重试，失败或未生效不恢复，legacy Storage-relative 快照仍可安全执行。

## Out of Scope

- 本阶段不引入付费闭源识别服务，也不把用户媒体名称或绝对路径发送给 LLM。
- 本阶段不复制 MoviePilot GPLv3 源码，不声称复刻当前闭源 Emby Server 的内部实现。
- 不要求首次交付支持音乐、有声书或成人内容的完整元数据识别；架构不得阻断未来独立 provider/领域扩展。
- 不把公共“共享识别库”作为自动匹配前提；首版纠错学习保持本地、可撤销。
