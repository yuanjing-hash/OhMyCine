# brainstorm: Server 管理端信息架构与仪表盘改版

## Goal

将当前以功能平铺和开发状态信息为主的 Server 管理端，改造成可承载完整媒体自动化产品的分组式后台。参考 MoviePilot 仪表盘的信息密度与卡片组织方式，但使用 OhMyCine 自己的媒体流水线、三层存储架构和 Cinema OS 视觉语言，不复制其品牌、栏目或页面细节。

## What I already know

* 当前左侧菜单把仪表盘、用户、角色、审计和未来媒体功能全部平铺在同一层，层级混乱。
* 当前主页主要展示用户、角色、审计和安全基线，更像开发/系统状态页，不像日常媒体自动化控制台。
* 用户希望仪表盘保持独立，业务菜单按发现、订阅、整理/自动化和系统分组。
* 账户、角色和权限必须收拢到一个“用户管理”菜单项内。
* 当前登录用户修改自己的资料、密码和会话，应放在右上角头像菜单，不混入管理员用户管理入口。
* 右上角需要日志、通知和用户头像区域。
* 用户在需求讨论中提供的参考图采用固定侧栏、顶部搜索/工具区和不同跨度卡片网格；项目文档不记录提供者本机的绝对路径。
* OhMyCine Server 的核心是 `Discover → Download → Transfer → Import → Notify` 与 `Connections → Storage Destinations → Category Rules`。

## Assumptions (temporary)

* 仪表盘应采用“内容 + 运维混合型”，既有媒体/订阅信息，也有存储、任务和系统健康状态。
* 豆瓣/TMDB 聚合属于发现与探索，不改变 AI 推荐主要位于 Player 侧的边界。
* 未实现或未配置的数据不显示虚假零值，应显示可执行的配置引导或空状态。

## Open Questions

## Requirements (evolving)

* 左侧侧栏一级结构：独立仪表盘 + 发现 + 订阅 + 媒体自动化 + 系统。
* 发现包含推荐、探索；聚合 TMDB/豆瓣等公开元数据和趋势信息。
* 订阅包含订阅管理、工作流、日历。
* 媒体自动化包含任务中心、下载管理、媒体整理、STRM/入库、文件管理。
* 系统包含连接与存储、站点管理、插件、用户管理、设置。
* 用户管理内部通过页签或二级导航容纳账户、角色与权限、会话；不再平铺多个侧栏入口。
* 审计/运行日志不作为普通侧栏一级入口，合并到右上角日志中心；通知单独使用通知中心。
* 头像菜单包含我的资料、修改密码、登录会话、界面偏好和退出。
* 导航分组、子页面、按钮和右上角入口都继续使用稳定 permission code 控制，后端 API 仍为安全边界。
* 仪表盘采用 12 列响应式卡片网格，不同信息使用不同跨度与优先级。
* 视觉保留 OhMyCine 深色影院感、青蓝/翡翠主色和克制玻璃质感，不采用 MoviePilot 的紫色品牌语言。

## Proposed Dashboard Hierarchy

* 顶部：问候、Server 总状态、全局搜索、日志、通知、用户头像。
* 第一层：媒体概览、存储空间、连接健康、活动任务。
* 第二层：媒体流水线状态、近期入库/整理、后台任务队列。
* 第三层：下载速率与队列、订阅日历、快捷操作。
* 底部内容区：来自发现模块的趋势/推荐 Hero 或海报卡片。

## Decision (ADR-lite, confirmed)

**Context**: 当前导航和主页是为了验证 RBAC 搭建的基础版本，不能承载完整 Server 产品。

**Decision**: 采用分组式侧栏、统一顶栏和混合型卡片仪表盘；账户/权限收拢到用户管理，个人资料移入头像菜单，日志/通知移入顶栏。

**Consequences**: 后续业务模块可以按领域接入而不继续增加平铺菜单；仪表盘 API 需要逐步提供聚合摘要，但 UI 改版阶段不得伪造未实现数据。

## Confirmed Decisions

* 仪表盘采用“内容 + 自动化运维”的混合型方案。
* 日常 Server 状态、媒体流水线、订阅信息和发现内容都属于主页，但通过视觉层级区分主次。
* 首屏优先显示媒体概览、存储/连接健康、活动任务和流水线；发现内容 Hero 放在这些卡片之后，不抢占 Server 控制台的主要信息层级。
