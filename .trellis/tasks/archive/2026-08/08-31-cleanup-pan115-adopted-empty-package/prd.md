# 115 入库空包收尾与回收站定时清理

## Goal

一次完成两项 115 数据源收尾能力：自动监听内容成功整理入库后回收任务认领的空作品包；并在 115 账号级配置中提供默认关闭的定时自动清空回收站能力及加密保存的操作密码，让长期自动化既不残留空壳，也可按用户明确授权收敛回收站。

## Deliverables

- `08-31-fix-pan115-ingest-empty-package`：修复自动监听/115 离线下载完成入库后的空来源作品包。
- `08-31-add-pan115-recycle-cleanup-schedule`：增加 115 账号级定时清空整个回收站设置、操作密码 UI 与持久调度。

## Requirements

- 两项能力必须保持独立语义：来源空包只进入 115 回收站；定时清空才会永久删除账号回收站中的全部内容。
- 同一 115 Connection 被多个 Storage/媒体库复用时，只存在一份操作密码、一份定时配置和一个调度实例。
- 操作密码继续复用现有 `recycle_password` AES-GCM 凭据边界，不新增第二份明文或密文字段。
- 全量清空默认关闭，启用时必须明确提示“不可恢复”，且只有连接管理权限可修改。
- 日志、任务 payload、审计、WebSocket 与普通 DTO 都不得泄漏操作密码、Cookie、provider ID 或真实路径。

## Acceptance Criteria

- [ ] 自动监听内容完整入库后，任务认领且确认为空的顶层来源包进入回收站；监听根、非空目录和未认领内容不受影响。
- [ ] 115 数据源表单可设置操作密码、启用/停用定时清空并填写 5 段 Cron；默认关闭、默认周期为 `0 */7 * * *`。
- [ ] 到期任务只按 Connection 调度一次；重启可恢复，重复轮询不并发清空同一账号。
- [ ] 定时任务执行前重新确认连接启用、定时策略启用、配置 revision 与操作密码仍有效；配置改变后旧任务安全失效。
- [ ] 成功或失败均可在数据源页面看到上次状态、上次时间和下次计划时间，错误只暴露稳定错误码。
- [ ] 所有定向测试、Server 全量测试、WebUI lint/typecheck/tests、`go vet ./...` 与 `git diff --check` 通过。

## Out of Scope

- 清空“最近接收”目录、递归扫描并删除历史空目录。
- 提供“立即清空回收站”按钮。
- 永久删除来源空包，或把定时全量清空复用到精确 owned-item 清理接口。
- 复制 MoviePilot GPLv3 插件源码；仅借鉴其外部行为和默认值。
