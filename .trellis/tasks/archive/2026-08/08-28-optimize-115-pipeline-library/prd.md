# 优化115媒体管线与媒体库体验

## Goal

让 115 媒体整理和 STRM 同步真正按增量工作，并补齐 Server 管理端的媒体库浏览与管理体验：单文件整理不再无谓等待十几分钟、未变化的 STRM 不重复写入、推荐详情展开不白屏，用户能按媒体库浏览海报并执行元数据维护和受控的源文件删除。

## Background

- 用户实测整理一个已经位于 115 的文件耗时十几分钟，要求对照 `DDSRem-Dev/MoviePilot-Plugins` 的 115 转存、防风控和目录操作策略定位根因。
- 推荐详情页展开季度后路由仍停留在详情页，但主内容区全白。
- 115 STRM 增量任务连续产生新的 generation，并将约 76 个既有条目反复计为“更新”；用户期望只写新增/真正变化的条目，删除云端已不存在的映射，未变化条目直接跳过。
- 现有“系统 > 媒体库”配置页保留功能，但侧栏名称改为“媒体库管理”；“发现”下新增面向内容的“媒体库”页面。

## Requirements

### R1. 115 整理/转移性能

- 识别当前单文件整理过程中重复轮询、逐层建目录、重复列目录、风控等待或错误的完成判定。
- 参考 MoviePilot 插件的公开实现，但只采用能证明适合 OhMyCine 连接/媒体库/任务模型的策略。
- 对已在同一 115 账号中的媒体采用服务端转存/移动语义，不下载回本地再上传；目录创建和查询应缓存、合并或批量化。
- 防风控只约束高风险/高频 115 API 操作，不应给普通单次建目录或已确认成功的操作附加分钟级固定等待。
- 保留任务可观察性、幂等和失败重试，不能以“更快”为由吞掉错误或绕过完成确认。

### R2. 推荐详情展开白屏

- 修复剧集详情页展开季度/集数后全白的运行时异常。
- 展开、收起、无剧集数据、部分覆盖数据和重复点击均不得破坏页面。
- 错误应局部降级并可诊断，不能让整个路由内容消失。

### R3. 115 STRM 真增量同步

- 稳定定义 STRM 条目身份和期望内容；仅远端身份、目标相对路径或最终 STRM 内容实际变化时更新文件。
- 云端新文件创建对应 STRM；云端删除文件时只删除受该媒体库 manifest 管理且位于配置 STRM 根目录内的 `.strm`。
- 未变化条目计为跳过，不改写文件时间、不反复增加“更新”计数。
- generation 仍可记录每次运行，但运行结果必须准确区分写入、更新、跳过、自动清理和失败。
- 兼容现有 manifest/基线；必要迁移不得导致首次升级误删或全量重写。

### R4. 媒体库浏览与管理

- 保持当前媒体库配置页面和能力不变，将系统侧栏入口从“媒体库”改名为“媒体库管理”。
- 在“发现”分组新增“媒体库”入口，页面顶部可切换全部已配置媒体库，并按电影、电视剧等分类展示海报墙。
- 海报卡进入与推荐详情视觉/信息结构一致的详情页，并显示该媒体库中的实际文件/季集覆盖。
- 详情页支持修改元数据、重新刮削和删除媒体。
- 删除默认语义是删除该媒体条目对应的数据源文件：本地文件从受控媒体库根目录删除，115 文件通过对应连接删除；删除后同步清单/STRM/媒体服务器刷新状态。
- 删除属于高风险操作，必须展示将删除的媒体库、数据源和文件数量/范围，进行明确确认并写入审计；后端必须重新校验资源仍属于所选媒体库和配置根目录，禁止任意路径删除、跨库删除和符号链接逃逸。
- 批量删除、回收站/可恢复删除和其他云盘驱动的专有删除策略不纳入本轮，除非现有驱动已提供可安全复用的一致能力。

## Constraints

- 目标组件是 OhMyCine Server，不改 Player 的独立运行边界。
- 不照搬第三方插件的许可受限代码；只研究其公开行为、算法和 API 调用策略，并独立实现。
- 115 Cookie、路径、直链和删除目标不得出现在普通日志或非授权 API 响应中。
- 文件删除必须遵守配置根目录、路径规范化、权限和审计要求。

## Acceptance Criteria

- [ ] AC1：整理一个已位于同一 115 账号、目标目录已存在的单文件任务时，不再出现分钟级固定等待；测试能证明没有下载回传和不必要的重复目录/API 轮询。
- [ ] AC2：目标目录不存在时只创建必要层级；限流/风控只在服务端明确返回相应信号或达到受控频率阈值时退避，任务结果保持幂等。
- [ ] AC3：推荐详情展开和收起季度后页面持续可见，空数据与异常数据有局部错误态，前端测试覆盖导致原白屏的输入。
- [ ] AC4：连续两次扫描完全相同的 115 树时，第二次 STRM 运行 `write=0`、`update=0`、`cleanup=0`，既有 `.strm` 内容和修改时间不变，条目计入 `skip`。
- [ ] AC5：新增、改名/移动、远端身份或最终内容变化、云端删除分别产生正确的写入/更新/清理结果；清理只触及 manifest 管理的 STRM 根内 `.strm`。
- [ ] AC6：升级已有媒体库/manifest 后不会因格式迁移无条件全量重写或误删，统计和运行历史与实际文件变化一致。
- [ ] AC7：系统侧栏显示“媒体库管理”，原配置页路由和功能保持可用；发现侧栏新增“媒体库”。
- [ ] AC8：发现媒体库页能切换多个媒体库、按分类分页展示海报，并从海报进入详情查看真实库内覆盖。
- [ ] AC9：管理员能修改元数据、重新刮削；操作失败有局部反馈且不会破坏原有媒体记录。
- [ ] AC10：管理员删除媒体时必须看到精确影响范围并二次确认；后端越权、路径逃逸、跨库目标和过期目标均被拒绝，成功删除后清单、STRM 和刷新任务达到一致状态并留下无敏感信息的审计记录。
- [ ] AC11：相关 Go 测试、Web UI 单元测试、类型检查、构建和 lint 通过；API 契约与架构/安全文档同步更新。

## Out of Scope

- 重做现有媒体库配置页。
- 修改 Player 媒体库 UI。
- 允许普通用户绕过权限或无确认直接删除源文件。
- 为所有未来云盘驱动一次性实现删除；本轮至少覆盖当前已配置并能安全证明语义的本地和 115 数据源。
