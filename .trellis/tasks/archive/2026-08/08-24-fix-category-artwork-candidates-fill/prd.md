# 修复分类封面候选筛选与少海报构图

## Goal

让本地与 115 媒体库的每个实际分类都能使用已有 TMDB 海报生成完整的 1920×1080 风格 3 分类封面；作品不足九个时按参考插件补齐九个槽位，不能只露出顶部小图或退回固定分类图。

## Evidence

- 真实数据库中“动画电影”和“国漫”的识别状态为 `unrecognized`，但识别记录已有 TMDB ID、分类和完整 `snapshot.poster_path`；旧查询硬性要求 `status=matched`，错误丢弃了可用海报。
- “外语电影”和 115“外语电影”只有一个作品；旧渲染仍按三张一列的完整列高定位，导致单张海报随整列旋出画布。
- 参考 `justzerock/MoviePilot-Plugins` 的 `prepare_library_images()` 会在多图模式下将已有图片复制补齐 `1.jpg`～`9.jpg`，再交给 `style_static_3.py` 渲染。

## Requirements

1. Server 以当前分类条目和有效 TMDB 元数据快照为候选依据，不因低置信度状态丢弃已存在的安全海报路径。
2. 候选仍严格隔离 `library ID + category name + media type`，并按识别记录去重。
3. 1～8 张有效海报需确定性循环补齐到 9 个槽位，再使用既有 `315426987` 排列；输出尺寸保持 1920×1080。
4. Player 独立媒体库的 1～8 张本地候选采用同样补齐策略；只要至少一张候选就标记为动态生成。
5. 无有效海报时继续安全回退；Emby/Jellyfin 原生封面及 Server 顶层固定入口图不受影响。
6. 回归测试覆盖 1、2、3、4、8、9 张候选以及低置信度但含有效快照的分类。

## Acceptance Criteria

- [x] 本地“动画电影”“国漫”“外语电影”和 115“外语电影”均从各自真实分类条目的有效 TMDB 快照生成完整风格 3 分类封面。
- [x] 单作品分类补齐完整九槽位构图，不出现顶部露头或大片纯渐变。
- [x] 候选不会跨媒体库、分类或电影/剧集类型串用。
- [x] Player 独立本地/原始来源单作品分类也生成风格 3。
- [x] Server 与 Player 相关测试、类型检查、lint 和构建通过。
- [x] 代码提交后按既有发布流程推送 `develop` 并发布新的 Player Beta。
