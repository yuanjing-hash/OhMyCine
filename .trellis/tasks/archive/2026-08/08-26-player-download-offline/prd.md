# Player 下载管理与完整离线播放

## Goal

把 Player 现有的单文件即时下载队列升级为独立、可恢复、跨数据源的下载与离线播放系统。用户能够从媒体详情、剧集和播放上下文中下载内容，在统一下载中心控制队列，并在原数据源、Server、Emby 或网络不可用时继续浏览完整媒体详情并优先播放已经下载的本地文件。

## Background

- Player 已有桌面与 Android 下载基础：SQLite 任务表、断点续传、聚合下载规划、媒体操作菜单及 SAF 目录授权。
- 当前任务入队后立即启动，没有统一并发调度、单任务分段、全局限速、实时速度或剩余时间。
- 当前取消只进入 `cancelled` 状态，任务和分片仍保留，并且 UI 把取消任务作为可重试任务展示。
- 当前下载入口是独立右下角圆钮，下载目录仍在通用设置中；PC 右侧悬浮工具栏没有下载管理入口。
- 当前 `SourceMetadataCache` 只是进程内 Map，无法保证重启或离线后进入详情页。
- 当前原生下载解析支持 local、OpenList/Alist、CloudDrive2、WebDAV、123、夸克和 Emby/Jellyfin，但不支持 ServerDataSource；Server 已提供受设备令牌保护、可重复解析本地文件或115短期302的媒体流端点。
- 下载任务已经只保存稳定数据源/媒体身份，不保存 URL 或 Header；本任务必须保留并扩展这一安全边界。

## Requirements

### R1. 统一下载能力与下载入口

- 媒体操作系统继续作为下载入口的唯一业务入口，支持桌面右键和触摸设备长按。
- 电影、单集、当前播放项可下载当前选定版本和清晰度；季和剧集可规划聚合下载，并在确认前显示文件数量与已知总大小。
- 同一媒体存在多个版本时必须允许选择版本；提供者发布多个静态可下载清晰度时必须允许选择清晰度。
- 不支持安全下载的数据源必须隐藏或禁用下载操作并给出明确原因。
- 支持现有本地/远程数据源、Emby/Jellyfin、Server 物理媒体库以及 Server 在线插件媒体；Server 管道“下载入库”与 Player“下载到本机离线观看”必须是两个不同动作。

### R2. 下载设置与调度

- 下载目录、同时下载任务数、单任务分段/线程数和全局速度上限迁入下载管理页面的“设置”分页，不再保留在通用设置页。
- 同时下载任务数与单任务分段数必须分别配置；速度上限支持“不限速”。
- 所有配置必须持久化，并在桌面与 Android 使用同一语义；Android 可以因 SAF 能力退化为单流写入，但仍必须遵守全局并发与限速。
- 调度器按队列顺序公平启动任务，暂停任务不占下载槽；应用意外退出后的运行中任务在下次启动时按断点恢复，用户主动暂停的任务保持暂停。
- 下载进度事件至少包含状态、已下载大小、总大小、实时速度、剩余时间和活动分段数。

### R3. 可刷新地址与安全续传

- 持久化任务只保存稳定媒体身份、版本/清晰度身份、目标位置和断点事实，禁止保存播放 URL、302 Location、Authorization、Cookie、API Key、Server 设备令牌或 CDN 参数。
- Server 媒体下载必须按稳定 entry/在线媒体版本身份重复请求 Player API；Server 本地文件直接流式读取，115或其它受支持云源每次解析获得新的短期302地址。
- Emby/Jellyfin 必须按 `sourceId + itemId + mediaSourceId` 重新解析同一媒体版本。临时重定向失效时重新请求 PlaybackInfo/静态流入口，不复用旧 Location。
- 对 URL 过期、401/403/404/410、可恢复网络中断和不完整响应执行有限次数的内部重新解析；内部刷新成功时继续原任务，不向用户显示失败。
- 只有内部恢复耗尽后任务才进入“失败”，此时才允许用户点击“重试”。
- Range 续传前必须验证响应范围与媒体实体身份。身份一致才从断点继续；身份变化、Range 不可信或分片事实不一致时只清除该任务残缺文件并从头开始，绝不拼接不同媒体内容。

### R4. 明确的任务状态与取消语义

- 用户可暂停、继续、取消运行中或排队任务；失败任务可重试。
- 用户取消后必须停止网络/文件写入、删除该任务的临时分片、断点和任务记录，并从 UI 消失；不得保留 `cancelled` 卡片或显示“重试”。
- 如果临时文件清理暂时失败，下载任务仍从用户队列移除，内部清理记录在后续启动时继续处理；清理记录不得表现为可重试下载。
- 聚合任务取消时停止并删除尚未完成的子任务，已经完成并形成离线包的媒体继续保留。
- 失败重试沿用稳定媒体身份和安全断点；用户主动暂停显示“继续”，不显示“重试”。

### R5. 下载管理界面

- PC 右侧悬浮工具栏增加下载管理入口和活动任务徽标，不占用播放器右下角控制区域。
- 移除当前独立右下角下载圆钮，增加独立下载管理路由。
- 下载管理至少包含“进行中 / 已完成 / 失败 / 设置”分页，并支持聚合任务展开。
- 进行中显示进度、实时速度、已下载/总大小、剩余时间和任务操作；已完成可打开离线详情、打开文件位置、删除记录或删除记录及文件；失败显示安全错误和重试。
- Android/移动端在现有 Quick/底部导航信息架构中提供下载管理入口，所有操作必须是可触摸目标，不能依赖悬停。

### R6. 完整离线媒体包

- 视频完成后必须建立持久化离线媒体包，保存来源身份、作品/季/集层级、当前版本/清晰度、详情快照和本地文件定位。
- 必须将海报、背景图、单集图片等离线展示资源复制到不受普通图片 LRU 清理影响的离线资产区域。
- 必须尝试保存当前媒体可安全取得的外置字幕和弹幕；内嵌字幕继续随视频文件使用。
- 视频和详情快照完成即视为“可离线播放”。附件失败时显示“视频已完成，附件待重试”，允许单独重试附件，不删除或降级已完成视频。
- 离线包不得保存签名 URL、Provider 临时 URL、请求 Header 或凭据。删除离线包时只删除该包精确拥有的资产。

### R7. 离线浏览与本地优先播放

- Player 增加内置“离线内容”虚拟数据源，能够在冷启动且所有远程来源不可用时列出电影、剧集、季和单集并打开详情。
- 原数据源详情请求失败时，如果存在对应离线快照，媒体详情路由必须自动回退到离线内容，而不是显示空白或阻止进入。
- 播放解析必须首先查找精确匹配的已完成本地版本；文件存在且校验有效时始终播放本地文件，即使网络和原数据源均正常。
- 本地文件缺失或校验失败时清除错误“已下载”状态，并在来源可用时回退在线播放；不得把损坏文件交给播放器。
- 离线播放自动加载离线字幕和弹幕，并继续使用现有本地播放历史与播放偏好。

### R8. 已下载标识

- 通用媒体卡片、首页、搜索结果和详情页显示统一下载状态，不能在各页面分别计算。
- 下载标识位于海报左上角，并与现有右下角绿色“已播放”标识在位置、图标和含义上明确区分，不能只依赖颜色。
- 电影或单集完成时显示“已下载”；剧集部分下载显示下载数量，例如 `3/12`；全部已下载显示完整状态。
- 状态必须由一次批量加载的离线索引和增量事件驱动，禁止每张海报单独调用原生命令形成 N+1 查询。

### R9. 兼容与迁移

- 现有下载设置和任务数据库必须原地迁移，不能要求用户清空 Player 配置。
- 旧 `cancelled` 记录迁移后删除并清理可确认归属的临时文件；旧运行中/排队任务进入新调度器；旧用户暂停任务保持暂停。
- 能确认最终文件仍存在的旧完成任务建立最小离线媒体记录，并在来源下次可用时补齐详情/附件；不能确认文件的记录不得显示已下载标识。
- 修改默认下载目录只影响未来任务，不能令旧目录中的离线包失效。

### R10. 安全、错误与平台边界

- 所有目标文件必须约束在用户已选择的桌面目录或 Android SAF 授权树中，防止路径穿越、符号链接逃逸和文件名注入。
- 跨源302必须删除 Provider 私有 Header；HTTPS 不能降级到 HTTP。
- 日志、错误、数据库、事件和诊断不得包含临时 URL、签名参数、Authorization、Cookie 或凭据。
- 用户可见错误必须区分凭据失效、来源不可达、磁盘空间不足、Range 不支持、媒体身份变化、文件写入失败和附件失败，同时保持敏感信息脱敏。
- Player 无 Server 连接时，本地、Emby/Jellyfin及其它直接数据源下载和离线播放仍然完整可用。
- 本任务实现期间只修改 `player/`；另一个并行任务拥有 `server/`。ServerDataSource 下载必须优先复用现有 Player stream/playback API，发现契约缺口时记录为后续 Server 子任务，不能在本任务交叉修改 Server。

## Acceptance Criteria

- [ ] 在设置同时下载数为 2、单任务分段数为 4 后，最多只有两个媒体任务同时运行；支持 Range 的桌面下载每个任务最多使用四个分段，配置在重启后仍生效。
- [ ] 全局限速启用时所有活动任务的合计速度保持在设置范围内，UI 持续显示实时速度和剩余时间；关闭限速后不人为节流。
- [ ] Server 115 下载进行到中途时让短期地址失效，Player 能重新请求 Server、验证同一媒体身份并从安全断点继续，最终文件大小和内容校验正确。
- [ ] Emby 返回临时302或旧流地址失效时，Player 能按同一 item/media source 重新解析并继续；凭据失效时任务进入失败且只显示脱敏错误。
- [ ] 点击取消后任务卡片消失、任务记录和临时分片被删除，重新打开 Player 后不会出现该任务，也不会出现“重试”。
- [ ] 网络失败后的任务进入失败分页并可手动重试；用户暂停的任务显示“继续”，成功任务进入已完成分页。
- [ ] 下载电影或单集后，海报左上角出现独立下载标识；观看完成标识仍保留在原位置。部分剧集显示正确的已下载集数。
- [ ] 停止 Server/Emby并断网后重新启动 Player，仍能从“离线内容”打开完整详情，看到已保存图片，并播放本地视频、字幕和弹幕。
- [ ] 在线来源可用时点击已下载内容仍优先播放本地文件；手动移除本地文件后状态被纠正，并在来源可用时回退在线地址。
- [ ] 字幕、弹幕或图片附件失败不会删除视频，完成页显示附件待重试并能单独恢复。
- [ ] ServerDataSource 的本地文件、115媒体和在线插件媒体均可通过稳定身份创建 Player 本地下载；Server“下载入库”动作仍保持独立。
- [ ] SQLite schema、日志、Tauri 事件和 Vue 状态检查证明没有持久化或输出 URL、Header、Cookie、API Key、Server device token 或302签名参数。
- [ ] Windows 原生运行验证、Android SAF/前台通知验证、TypeScript 检查、Rust 检查及下载专项回归全部通过。

## Out of Scope

- 不把 Player 下载任务上传到 Server 媒体库，也不改变 Server 的 qBittorrent、115离线下载或转移入库队列。
- 不实现任意实时转码来制造数据源没有提供的离线分辨率；首版只下载 Provider 明确提供的静态版本/清晰度或原始文件。
- 不支持 DRM 加密、必须依赖不可导出会话或不允许离线保存的媒体。
- 不实现跨设备同步下载文件、自动保留天数或按空间自动淘汰。
- iOS 下载执行器保持后续平台工作；本任务必须保证共享契约不会阻碍未来实现。
- 不在本任务修改 `server/`、Server Web UI、Server数据库或Server API实现。
