# 统一媒体搜索与自动订阅管线

## Goal

把 Server 目前割裂的“影视推荐/作品详情”和“PT 资源探索”整合为以稳定媒体身份为中心的完整流程：用户既可以从推荐进入作品，也可以先按关键词搜索 TMDB 海报并进入同一个作品详情；从作品详情发起资源搜索时，Server 自动使用该作品的中文名、别名、原名和英文名做受限聚合搜索。电视剧详情同时展示媒体库已有/缺失的季集状态，并支持创建能够定时发现缺集、自动搜索、自动下载和复用既有入库流水线的订阅。

## Background and confirmed facts

- 当前推荐作品可以进入 `DiscoveryDetailView`，详情页提供“按标题搜索资源”和“按 TMDB ID 搜索”，两者都直接跳到资源探索页；订阅按钮只是提示占位（`server/webui/src/views/DiscoveryDetailView.vue:28`, `:37`, `:59`）。
- 当前 PT 搜索 API 是 `/api/v1/discovery/pt-search` / `stream`，资源结果通过短期 `result_token` 交给现有下载服务；下载完成后已有识别、整理、Transfer、媒体库导入和通知链路（`server/internal/httpserver/router.go:189-199`）。
- 当前 Server 已有 TMDB 推荐与详情、TMDB `GetByID/Search`、媒体库按 `work_key` / `tmdb_id` 聚合和按季集列出已入库文件的能力，但作品详情没有跨媒体库覆盖率投影（`server/internal/services/media_catalog.go:76`, `:158`）。
- `follows.*` 权限和订阅导航占位已经存在，但 follow 模型、服务、API、调度 Worker 和真实管理页尚未实现（`server/webui/src/navigation.ts:57-59`）。
- MoviePilot v3 已按源码而非印象完成专项分析，结论记录在 `research/moviepilot-v3-analysis.md`。

## Requirements

### R1. 统一媒体发现入口

- Server Web UI 的搜索入口支持先按关键词搜索 TMDB 电影/电视剧海报，而不是直接把自由文本提交给 PT 站点。
- 搜索结果以稳定的 `media_type + tmdb_id` 标识作品，点击后进入与推荐卡片完全相同的作品详情页。
- 推荐、TMDB 关键词搜索、相关推荐和类似作品复用同一详情路由与同一操作区，不产生两套详情页。
- 保留“直接按原始关键词搜索站点资源”的高级入口，供无法识别或确实需要模糊搜索时使用，但它不是默认搜索路径。

### R2. 基于作品身份的多名称聚合资源搜索

- 从作品详情发起资源搜索时，后端必须先用 TMDB 身份读取权威元数据，再生成有顺序、去空、去重和有数量上限的查询词。
- 查询词至少覆盖当前中文标题、原始标题、英文标题和 TMDB 可获得的替代标题；不能只依赖页面传回的显示标题。
- 多个查询词的多站点结果汇总为一次搜索会话，按稳定资源身份去重，并统一执行当前识别、季集匹配、排序和安全 token 投影。
- 受站点并发、速率限制和取消信号约束；单个别名或单个站点失败不得抹掉其它成功结果。
- 直接原始关键词搜索仍只搜索用户输入的词，避免把模糊搜索误当成已确认作品。

### R3. 作品详情媒体库覆盖率

- 电视剧详情展示整剧汇总：TMDB 总季/总集、已入库季/集、缺失季/集和当前数据新鲜度。
- 每季展示 `已入库 / 部分缺失 / 全部缺失 / 未播完或元数据不完整`，展开后可见逐集状态；特别篇（Season 0）与未播集必须有明确规则。
- 覆盖率由所有当前用户有权读取且启用的 Server 媒体库聚合，按 `tmdb_id + media_type + season + episode` 计算并去重，不能依赖标题模糊匹配冒充确定结果。
- 电影详情展示 `已入库 / 未入库` 和命中的媒体库，不显示虚假的分集数据。
- 媒体库未扫描、TMDB 季集详情不可用或识别不完整时显示 `未知/待扫描`，不得把未知当作缺失并触发自动下载。

### R4. 电视剧订阅管理

- 电视剧详情提供 MP 风格的季选择订阅界面：显示季海报/名称、总集数、入库状态、已订阅状态，并允许选择一个或多个季。
- 订阅是当前用户拥有的持久对象，绑定稳定 TMDB 身份和一份可编辑、可版本化的执行策略快照；创建界面用全局默认值预填，但保存后不再被以后修改的全局默认值静默改变。
- 执行策略快照至少包含目标季、启用站点及站点优先级、下载器、目标媒体库、运行周期、质量/包含/排除规则、单次资源上限和下载优先级；只保存稳定 ID 与非敏感规则，不复制 Cookie、passkey、下载地址、凭据或绝对路径。
- 编辑订阅会生成新的配置修订；已经开始的运行继续使用启动时修订，下一次运行才使用新修订，以保证运行可解释且不会执行一半突然换规则。
- 支持创建、查看、编辑、暂停、恢复、删除和“立即搜索”；管理列表显示已入库/目标总集、缺失集、最近搜索结果、最近错误和下次执行时间。
- 同一用户、同一 TMDB 电视剧、同一季不能产生重复的活动订阅；重复创建应返回现有订阅或明确冲突。
- 本期普通订阅目标是补齐缺集，不实现 MP 的洗版/最佳版本升级模式。

### R5. 自动搜索、下载和入库

- 调度器按订阅间隔或“立即搜索”创建可恢复、可观察的 follow-search Job，不在 HTTP 请求内执行长耗时搜索。
- 每次运行先重新获取 TMDB 季集信息并与媒体库覆盖率对账；只有已播出且被确定为缺失的集才进入搜索目标。
- 搜索必须复用 R2 的媒体身份与多名称聚合能力，并将目标季集范围带入结果识别和过滤。
- 自动选择结果必须是确定性的：先排除不匹配作品/季集和重复资源，再按站点优先级、种子健康度、发布时间及配置过滤排序；同一目标集已有活动下载或已入库时不得重复提交。
- 选中资源后复用现有 `DownloadService → recognition → transfer → MediaLibrary → refresh/notify` 流水线，禁止另建绕过安全边界的下载/移动实现。
- 没有合格资源时订阅保持活动并记录本次未命中；配置无效、身份不明、覆盖率未知或候选无法证明覆盖目标集时进入可见的阻塞/失败状态，不静默下载。普通排序并列由稳定资源键确定性裁决。
- 下载完成和媒体库重新扫描后更新覆盖率与订阅进度；目标季全部补齐时标记完成，后续 TMDB 增加已播集时可重新进入待搜索状态。

### R6. 权限、安全与可观察性

- 复用并补齐 `follows.read_own/read_all/create` 权限，新增更新、删除、执行等操作所需的细粒度权限；普通用户只能读取和操作自己的订阅。
- Job、API、日志和事件只暴露安全 DTO；PT Cookie/passkey、真实 torrent URL、下载器凭据、绝对路径和临时地址不能进入订阅记录、浏览器状态或日志。
- 创建自动下载订阅前必须验证下载器、目标媒体库、下载暂存和站点配置可用；配置失效后停止自动提交并提供可操作错误。
- 状态变化通过现有任务/事件基础设施呈现，至少覆盖订阅运行、找到缺集资源、已提交下载、未命中、失败和完成。

## Acceptance Criteria

- [ ] 在 Server Web UI 输入剧名后先看到 TMDB 海报结果；点击任一结果进入与推荐卡片相同的详情路由。
- [ ] 从作品详情搜索资源时，可观察到中文名/别名/原名/英文名的受限聚合搜索；最终列表去重且单个来源失败不会丢失其它结果。
- [ ] 直接模糊资源搜索仍可用，并且不会伪造稳定 TMDB 身份或自动扩展多语言词。
- [ ] 已配置媒体库中存在的电视剧能在详情页显示准确的已入库/缺失季集，逐集状态与媒体库目录事实一致。
- [ ] 未扫描或无法确定身份的数据呈现未知状态，且订阅 Worker 不会据此创建下载。
- [ ] 用户能从电视剧详情选择季并创建订阅，也能在订阅管理页暂停、恢复、删除和立即执行。
- [ ] 创建订阅时可以检查并覆盖季、站点、下载器、目标库、周期、质量/包含/排除规则、资源上限和优先级；保存后的旧订阅不随全局默认变化，编辑后的新修订从下一次运行生效。
- [ ] 订阅运行能识别已播缺集、搜索并只提交覆盖缺集的最佳合格资源；重复运行不重复下载同一集。
- [ ] 自动提交的任务走现有下载、识别、Transfer、入库和媒体服务器刷新链路，下载管理与任务中心可追踪完整状态。
- [ ] 无结果、站点失败、配置失效和安全歧义均产生可见且可重试的状态，不会静默下载错误资源。
- [ ] 普通用户无法读取或操作他人订阅，任何 API/日志/事件都不泄露凭据、真实 torrent URL 或绝对路径。
- [ ] 后端相关 Go 测试、Web UI 单测/typecheck/lint/build 和迁移测试通过；OpenAPI、Server 架构与 roadmap 同步更新。

## Out of Scope

- 本期不实现 MP 的洗版、最佳版本升级、订阅分享、热门订阅、音乐订阅和字幕订阅。
- 本期不新增 PT 站点适配器，也不改变既有凭据存储和下载器协议。
- 本期不让 Player 基础播放依赖 Server；改动范围是 Server API、调度和 Server Web 管理界面。
- 本期不依据未上映/未播出 TMDB 条目提前下载，也不把标题相似度作为自动下载的唯一授权依据。

## Key Product Decisions

- 默认交互固定为 `关键词 → TMDB 海报搜索 → 统一作品详情 → 多名称资源聚合 → 下载/订阅`；直接原始关键词搜种子只作为高级入口。
- 自动订阅采用 MP 风格的“创建时配置完整执行策略”体验：全局默认只预填新订阅，保存后形成可编辑、可版本化快照。
- 自动选择必须确定、保守并可解释；结果身份、季集覆盖或排名存在安全歧义时不自动下载。
- 本期只做电视剧普通缺集订阅，不做洗版、最佳版本升级、分享、热门、音乐或字幕订阅。
