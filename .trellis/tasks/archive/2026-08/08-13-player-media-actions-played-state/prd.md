# Player 媒体操作菜单与已播放状态

## Goal

为 Player 建立跨桌面与移动端一致的媒体操作体系：桌面右键、手机长按和播放页右上角菜单使用同一套来源感知动作；修复手机播放画面长按同时触发倍速与桌面右键菜单的问题；补齐本地媒体的已播放状态，并将 Emby 支持的状态与操作回传到服务端。

## Background

- Player 播放页在根节点监听 `contextmenu`。手机长按画面时，系统合成的右键事件会打开桌面播放菜单，同时触发现有长按倍速手势。
- `MediaCard` 与 `MediaGrid` 已预留 `contextmenu` 事件，原始文件源海报墙已有“识别/修正元信息”的局部菜单，但首页继续观看、详情页和其他海报入口尚未使用统一菜单。
- Emby 已读取 `UserData.PlaybackPositionTicks` / `PlayedPercentage`，播放完成时也会调用 Emby 标记已播放接口；统一 `DataSource` 尚无标记已播放、收藏、删除、刷新元数据等能力契约。
- Player 本地 `playback_history.sqlite` 已保存 `completed`，但当前只暴露继续观看查询，没有手动标记已播放/未播放、单条移除和跨页面完成态展示。
- 原始文件源当前按只读模型实现，本地刮削和分类不得写回远端目录；任何实际文件删除或远端写操作都属于架构与安全边界扩展。

## Requirements

### R1 移动端播放长按与播放菜单

- 手机/触摸端在播放画面长按时只执行现有长按播放行为：右侧长按倍速，左侧长按连续后退；不得同时打开桌面右键菜单。
- 真实鼠标右键在桌面播放画面继续打开播放上下文菜单。
- 手机播放页不显示桌面浮动右键菜单；其中仍有价值的动作迁入右上角现有工具菜单/面板。
- 触摸合成的 `contextmenu`、真实鼠标右键和 Alt 模拟触摸必须可区分，不能破坏 Windows 触屏设备或桌面测试手势。

### R2 全局自定义上下文菜单与输入规则

- 桌面端：支持操作的媒体/媒体库对象使用自定义右键菜单；其他区域统一阻止浏览器/WebView 原生“刷新、另存为、检查”等菜单。
- 移动端：支持操作的媒体/媒体库对象通过长按打开响应式操作面板；其他区域长按不得弹出桌面右键菜单或浏览器原生菜单。
- 同一动作定义、可见性、禁用原因、危险等级和执行状态由共享领域层提供，页面不得各自硬编码不同菜单。
- 菜单只显示对象类型和当前 DataSource 真正支持的动作；不交付无实现的空按钮。

### R3 继续观看与已播放状态

- 首页继续观看条目提供：继续播放、标记为已播放/未播放、移出继续观看。
- Emby 条目的已播放/未播放操作回传 Emby，并刷新本地展示缓存；移出继续观看使用 Emby 对应状态/进度能力，不伪造只在 UI 消失。
- 非 Emby 条目由 Player 本地数据库保存已播放状态和进度；手动移出继续观看只移除/重置该条继续观看记录，不删除媒体。
- 自动播放到完成阈值后继续保存 `completed`，已完成项目不再进入继续观看，但完成状态仍可供媒体库、搜索、首页其他分区和详情页读取。
- 海报卡片在已播放时显示右下角勾选徽标；详情页在合适位置显示同一状态，并提供标记已播放/未播放动作。
- 剧集、季、系列的聚合完成状态必须有明确规则，不得仅凭任意一集完成就把整季/整剧标为已播放。

### R4 媒体对象操作菜单

- 媒体海报的目标动作集合包括：播放/继续播放、标记已播放/未播放、收藏/取消收藏、添加到播放列表、添加到合集、下载、下载到、编辑元数据、编辑图像、编辑字幕、删除、识别/刮削、刷新元数据。
- 媒体库对象的目标动作集合包括：进入媒体库、重新扫描本媒体库，以及来源真正支持的管理动作。
- Emby 支持的动作优先调用 Emby 原生接口；非 Emby 来源优先使用 Player 本地领域数据或当前原始文件源已有的本地扫描/刮削能力。
- 识别/刮削复用现有原始文件源手动识别与扫描缓存，不给 Emby 重复套用 Player 本地刮削流程。
- 非 Emby 来源的元数据本来就属于 Player 本地刮削资产。“编辑元数据、编辑图像、编辑字幕”只更新 Player 本地数据库与受控缓存，不生成或修改网盘/本地源目录中的 NFO、图片或字幕伴随文件。
- Emby/Jellyfin 的元数据、图像、字幕编辑直接兼容提供方原生功能与权限；不把提供方数据复制到 Player 本地刮削模型后再编辑。
- “刷新元数据”对非 Emby 表示重新识别/刮削并更新 Player 本地缓存，对 Emby/Jellyfin 表示调用提供方原生刷新接口。
- 收藏、播放列表、合集必须区分 Player 本地实体和提供方实体；跨来源集合不能泄露凭据、签名 URL 或本地绝对路径。
- Emby/Jellyfin 条目的收藏、播放列表和合集使用提供方原生实体与接口，并在操作后刷新提供方缓存；不额外双写一份 Player 本地副本。
- 非 Emby 条目的收藏、播放列表和合集由 Player 本地数据库管理，可跨本地文件、OpenList/Alist、CloudDrive2、123、夸克和 WebDAV 来源组织；仅保存稳定的 `sourceId + item/media identity` 与展示快照，不保存临时直链、Header 或凭据。
- 提供方原生集合与 Player 本地集合在 UI 中清楚标注归属；来源被删除或对象失效时保留可诊断的缺失项状态，并允许用户从集合中清理。

### R5 能力契约与反馈

- 在 DataSource/媒体操作服务边界建立显式 capability/action contract，覆盖可见、可用、禁用原因、确认要求与执行结果。
- 来源不支持的动作不显示；暂时缺少必要配置或权限的动作可显示禁用状态并说明原因。
- 操作成功后更新所有相关缓存与页面；失败只影响该动作，并显示可理解且脱敏的错误。
- 并发点击、重复请求和页面离开不能造成重复删除、重复添加或旧响应覆盖新状态。

### R5.1 下载与下载到

- “下载”保存到 Player 全局默认下载目录；该目录可在设置页查看和修改。
- 桌面端首次默认使用操作系统下载目录；Android 首次使用下载时通过 SAF 选择目录并持久保存授权。默认目录失效、权限被撤销或不可写时必须重新选择，不能静默写入应用缓存代替。
- “下载到”每次打开平台目录选择器并只对当前任务使用该位置，不覆盖全局默认下载目录。
- 本地文件已存在于本机时不显示普通“下载”，改为“复制到/另存到”；远程来源显示“下载/下载到”。
- 电影多版本、整季和整剧下载进入可观察的文件级队列，显示总体与逐文件进度，支持取消、失败重试、磁盘空间检查和可安全恢复时的断点续传。
- 下载经过 302 播放链时，不得保存 302 响应、代理 URL 或 `.strm` 文本。原生下载层必须通过当前 DataSource 的受控解析流程获得最终原始媒体 URL 和必要请求 Header，再把实际媒体内容写入目标目录。
- 最终原始 URL、Cookie、Authorization、Referer、签名查询和其他临时 Header 只存在于原生进程内存；Vue、路由、日志、下载任务数据库和导出配置只保存不透明来源身份与目标文件状态。
- 原始 URL 过期、Range 失效或重定向变化时，通过 DataSource 身份重新解析，不把过期直链作为永久断点信息；每次解析仍执行 HTTP(S) scheme、有限重定向、来源边界与响应校验。
- Android 长任务使用可见的系统下载/前台服务状态，避免应用退到后台后任务被无提示终止。

### R6 安全与只读边界

- 媒体菜单的“删除”先打开统一确认窗口，而不是立即执行。默认不勾选“同时删除源文件”，此时只从 Player/提供方媒体库删除或隐藏该条目，不删除底层文件。
- 勾选“同时删除源文件”后，无论本地文件还是网盘文件，都必须通过当前来源的受控删除能力删除真实源文件；不得退化为仅从本地索引隐藏，也不得在失败时显示成功。
- 来源账号缺少删除权限、驱动没有安全删除接口或对象范围无法可靠解析时，“同时删除源文件”不可执行，并明确显示原因。
- 删除确认必须清楚展示媒体名称、来源、将从媒体库移除的对象范围、将删除的源文件数量/路径摘要以及不可恢复提示；真实源删除需要比仅移出媒体库更强的确认。
- Emby/Jellyfin 等提供方拥有原生删除模型时，Player 兼容其接口、权限和对象范围，不强行把提供方聚合对象展开成 Player 自定义的文件级批量删除。
- Player 自有媒体库中的电影多版本、整季和整部剧允许在勾选后批量删除其全部受控底层视频、字幕和伴随文件。确认窗口默认折叠文件清单，展示总数与路径摘要并允许展开逐项查看；整季或整剧删除还必须输入作品名二次确认。
- 删除成功后同步清理或刷新该来源的索引、播放历史、缓存和页面状态；部分失败必须逐项报告，禁止把未删除文件从索引中静默抹掉。
- 删除、覆盖元数据、修改远端字幕/图像等写操作在执行前必须经过来源能力校验和明确确认。
- 本地文件操作必须约束在配置根目录，阻止路径穿越和符号链接逃逸；远端操作不得携带或记录凭据、签名 URL、Cookie 或 Authorization。
- 原始文件源仍默认只读浏览；只有用户在删除确认窗口主动勾选“同时删除源文件”时，才允许调用经过明确实现和校验的删除能力。这是显式、单次授权，不代表其他上传、重命名或覆盖能力自动开放。
- 删除媒体源配置、移出继续观看、从本地收藏/播放列表/合集移除、删除媒体实体必须是不同动作和文案。

## Acceptance Criteria

- [ ] 手机播放画面长按只触发倍速/连续后退，不出现桌面播放右键菜单；桌面鼠标右键行为不回归。
- [ ] 播放页右上角工具菜单包含迁移后的移动端播放操作，并在横竖屏均可用。
- [ ] 支持操作的海报与媒体库在桌面右键、手机长按时打开同一套来源感知操作；其他区域不显示浏览器原生菜单。
- [ ] 首页继续观看可继续播放、标记已播放/未播放和移除；Emby 状态回传服务端，非 Emby 状态保存在 Player 本地。
- [ ] 自动或手动完成状态可持久化，完成项目不进入继续观看，并在海报与详情页显示勾选标记。
- [ ] 聚合系列/季的完成规则有测试覆盖，不会因单集完成误标整个作品。
- [ ] 媒体与媒体库菜单只显示当前来源真实支持的动作，无空按钮。
- [ ] Emby/Jellyfin 收藏、播放列表和合集写入提供方；非 Emby 使用 Player 本地跨来源实体，二者归属清楚且不双写。
- [ ] 识别/刮削与媒体库重扫复用现有本地扫描能力；Emby 使用提供方能力。
- [ ] 非 Emby 元数据/图像/字幕编辑只修改 Player 本地数据库与受控缓存；Emby/Jellyfin 使用提供方原生编辑与刷新能力。
- [ ] 设置页可修改全局默认下载目录；“下载”使用默认目录，“下载到”使用一次性目录，Android SAF 授权可持久化且失效时明确恢复。
- [ ] 302/STRM/签名播放来源下载的是解析后的真实媒体内容，临时 URL 和敏感 Header 不进入前端、日志或任务持久化。
- [ ] 聚合下载具有文件级进度、取消、失败重试、空间检查和安全断点恢复行为。
- [ ] 删除确认默认只移出媒体库；勾选后可对已实现安全删除能力的本地/网盘来源删除真实源文件。Emby/Jellyfin 遵循提供方原生范围，Player 自有整剧/整季/多版本按可展开清单批量删除且要求加强确认，并准确处理权限不足、驱动不支持及部分失败。
- [ ] 所有危险写操作具有来源能力校验、明确确认、错误反馈和路径/凭据安全检查。
- [ ] Windows、Linux 构建与 Android 触摸交互检查通过；现有播放、弹幕、字幕、播放进度回传和数据源浏览无回归。

## Out of Scope

- 在没有官方/稳定写接口时伪造云盘写入能力。
- 把 Server 下载管线作为 Player 基础媒体菜单的硬依赖。
- 为尚未实现的动作展示点击后只提示“开发中”的菜单项。
- 跨设备同步 Player 本地收藏、播放列表、合集和已播放状态；可作为后续 Server 增强。
