# 修复 Server 媒体库封面与分层返回

## Goal

让 Player 中的 Server 专区具备清晰、美观且真实的媒体库导航：媒体库和分类卡片有稳定封面，只显示有内容的分类，并按当前浏览层级逐层返回。

## Background

- Player 当前能从 Server 获取物理媒体库和插件在线媒体库，但媒体库卡片缺少可展示的封面。
- Server 分类接口会把分类规则中的空分类一并返回，导致只有一部电影的 115 媒体库仍显示大量空分类。
- Server 专区的返回按钮只依赖路由历史，未优先消费数据源内部的媒体库/分类层级。
- 插件包目前只携带 WASM 入口，不具备向 Player 提供受控静态媒体库封面的通用能力。

## Requirements

- Server 内置物理媒体库必须返回同源、可认证访问的静态封面；至少覆盖本地存储和 115，未知类型有通用兜底。
- 插件清单允许声明一个包内静态媒体库封面，打包、校验、安装、更新和运行时读取流程必须保留该资源。
- 插件静态资源只允许受约束的包内相对路径和 PNG/JPEG/WebP，禁止路径穿越、SVG/HTML 和任意本地路径泄露；封面通过基于包摘要的同源只读 URL 提供，不携带设备令牌或安装路径。
- 官方 Bilibili 插件提供自己的原创静态封面；Player 通过通用 `posterUrl` / `backdropUrl` 契约消费，不硬编码 Bilibili 或 115。
- Server 分类接口只返回 `item_count > 0` 的分类，保留规则顺序，并为规则外已有内容提供稳定顺序和分类主题封面。
- Player 在 Server 专区内优先逐层返回：分类内容到分类列表、分类列表到媒体库列表、媒体库列表再返回上一页面；刷新后仍可从当前标识推导到所属媒体库层级。
- 桌面返回按钮与其他触发浏览器后退的入口复用同一层级返回逻辑。
- 保持旧 Server、旧插件和缺少封面的响应可用，Player 使用现有占位样式安全降级。
- 保留现有未跟踪目录 `.trellis/tasks/08-19-player-subtitle-danmaku-regressions/` 与 `server/.tmp/`，不得纳入提交。

## Acceptance Criteria

- [x] Server 专区根页面的内置媒体库与 Bilibili 在线媒体库卡片均显示对应静态封面。
- [x] 115 媒体库只有《七武士》所在分类有内容时，分类页只展示该分类，分类卡片有封面，进入后展示真实媒体海报。
- [x] 从 Server 媒体库列表进入媒体库、分类和内容后，返回按钮逐层回退，不会从子层级直接跳回主页。
- [x] 插件包静态资源的打包、校验、安装和摘要寻址读取均有回归测试，非法路径或格式被拒绝。
- [x] Server、Player、Plugin SDK 和 Bilibili 插件相关自动化检查全部通过。
- [x] 变更以 Conventional Commit 提交并推送到 `origin/develop`。
- [x] 发布新的 Player Beta，标签严格对应最新 `origin/develop`；若插件协议有变更，官方 Bilibili 插件同步升版并更新官方 Registry。

## Out of Scope

- 不生成用户自定义动态拼图封面，本轮使用 OhMyCine 原创静态主题封面。
- 不改变媒体扫描、TMDB 刮削、下载或播放协议。
- 不改动 Player 独立数据源的导航和封面策略。
