# 推荐发现与元数据聚合页面

## Goal

把 Server 管理端现有“推荐”计划页替换为真实的影视发现页面，让用户浏览公开榜单、进入作品详情并按需查找 PT 资源。

## Confirmed Facts

- Server 已有加密 TMDB 设置、API Key/读访问令牌兼容、自定义 API/图片地址、中文语言/地区配置和完整详情快照能力。
- 当前 TMDB 客户端已有搜索和详情能力，但还缺少趋势、热门、高分、上映和播出类发现接口。
- 管理端已有 `discovery.read`、推荐/探索计划路由以及仪表盘“发现内容”占位卡片。
- 豆瓣没有在当前代码中实现；首版使用公开网页/公开数据入口的清洁室 provider，不复制第三方移动端 API key、签名 secret 或 GPL 实现。

## Requirements

- 推荐服务采用 provider 接口；各 provider 返回标准栏目、作品摘要、来源、生成时间、缓存状态与下一页游标。
- TMDB provider 复用现有 Server TMDB 凭据和路由设置，不建立第二套 Token 配置。
- 首版必须同时上线 TMDB 与豆瓣双源。栏目覆盖电影与剧集，至少包括本日/本周趋势、热门、高分、正在上映/播出、即将上映、豆瓣热门与豆瓣 TOP250；成人内容默认关闭。
- 推荐卡片使用 provider 稳定身份，详情阶段补齐完整 TMDB 快照；多个来源只有在可靠外部身份匹配时合并。
- 页面提供 Hero、栏目横向浏览、筛选/搜索入口、分页、来源/更新时间、刷新、缓存状态和局部错误重试。
- 页面顶层在 TMDB/豆瓣之间切换，第二层按电影、电视剧、动漫筛选；默认使用中文地区数据，并通过缓存协议版本避免复用旧的错误语言结果。
- 统一详情展示人物头像、角色/职务、推荐和类似作品；图片继续使用同源受控代理。
- 推荐结果不提前搜索全部 PT 站；用户进入详情或点击“搜索资源”后才调用 PT 聚合搜索。
- 每个 provider 独立缓存、超时和请求预算；实时请求失败时可返回未过安全保留期的旧缓存并明确标注。
- 推荐响应不包含本地路径、站点凭据或下载源；提供方 API 错误只返回稳定安全码。

## Acceptance Criteria

- [ ] AC1: 配置有效 TMDB 凭据后，推荐页同时展示 TMDB 与豆瓣真实电影/剧集栏目、海报、评分、年份、来源和更新时间。
- [ ] AC2: TMDB 不可用时其它 provider 仍可工作；有可用旧缓存时页面明确显示缓存，完全无数据时显示可操作空状态。
- [ ] AC3: 点击推荐作品可打开统一详情并触发 PT 资源搜索，不需要重新输入片名。
- [ ] AC4: 刷新只更新目标 provider/栏目，不破坏其它栏目和用户当前分页位置。
- [ ] AC5: provider 返回重复作品时仅按可靠身份合并；标题相同但身份不明的作品保持分开。
- [ ] AC6: 页面遵循 Server 传统管理端样式，亮/暗主题、键盘操作和窄屏均可用。
- [ ] AC7: provider 缓存、分页、限流、故障隔离、字段清洗、身份匹配、RBAC 与 UI 状态有自动化测试。
- [ ] AC8: TMDB 请求保留规范化的 `zh-CN`/`CN`，豆瓣图片携带受控防盗链请求头，详情可展示人物头像、推荐与类似作品。

## Out of Scope

- 基于用户观看历史的 AI 个性化推荐。
- 自动替用户下载推荐内容。
- 在本阶段改造 Player 首页或 Player 本地 AI 推荐。

## Delivery Constraint

- 豆瓣访问失败、结构变化或限流不得阻塞 TMDB；有旧快照时标记为过期缓存，无快照时只让对应栏目进入可重试错误态。
